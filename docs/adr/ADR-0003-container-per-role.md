# ADR-0003: 容器化部署（每个角色独立容器）

> 状态：已接受
> 日期：2026-09-02

## 背景

参考项目 [ref-project] 是单二进制。本项目需决定沿用单二进制还是容器化。

## 决策

选择 **容器化部署，每个角色 Agent 独立容器**。

关键理由：
1. **A2A 协议要求隔离**：每个评审角色是独立会话，容器隔离防止上下文泄露
2. **可伸缩性**：QA/安全等评审角色可水平扩展 replicas
3. **宿主隔离**：各 AI 编码 CLI 可能有依赖冲突（Node 版本、环境变量），独立容器避免冲突
4. **故障隔离**：一个 Agent 容器崩溃不影响 Coordinator
5. **A2A 协议天然跨容器**：容器即角色边界，协议即契约

## 后果

- 正面：隔离性好，可伸缩，符合微服务最佳实践
- 负面：资源占用高于单二进制；多容器编排复杂度增加；调试需 docker logs 多容器
- 后续：MVP 早期用 in-process 模式（单容器内多 goroutine）降低门槛，容器化在 Phase 3 引入

# ADR-0004: 写角色串行执行（单写者模型）

> 状态：已接受
> 日期：2026-09-02
> 验证数据：ADR-0010

## 背景

前端和后端写角色都修改源码。需决定串行还是并行执行。

## 决策

**写角色串行执行，同一时刻仅一个写角色修改源码**。

关键理由：
1. **实测数据支撑**：ADR-0010 验证并发写同一文件丢失 75% 数据
2. **避免冲突**：代码层面冲突（两人改同一函数）需串行解决，不如一开始就串行
3. **审计清晰**：串行执行的写操作时间线清晰，审计日志无交叉
4. **评审角色不受影响**：PM/架构/QA/安全/DevOps 是只读评审，仍可并行

## 后果

- 正面：无数据丢失，审计清晰，实现简单（mutex 即可）
- 负面：写角色吞吐量受限（但质量 > 速度）
- 后续：若需并行，可按目录分区（前端改 src/frontend/，后端改 src/backend/），但 MVP 不需要

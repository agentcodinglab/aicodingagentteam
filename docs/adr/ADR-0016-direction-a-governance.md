# ADR-0016: 体系守护 — 性能基线 / a11y / Lighthouse / Go public API 文档\n\n> 状态：已接受\n> 日期：2026-09-05\n> 关联规范：docs/CONSTRAINTS.md、docs/standards/general.md、AGENTS.md §4\n\n## 背景\n\nJ/K/L 阶段收口后，项目已具备：\n\n- 核心包测试覆盖率 ≥80%（CONSTRAINTS 红线）\n- 端到端集成测试 + proof-pack（ADR-0015）\n- 安全加固：gitleaks + Semgrep + Trivy + govulncheck\n- 9 语言 + 暗色霓虹 + 最佳实践首页（docs-site.yml）\n\n但存在四类长期治理缺口：\n\n1. 性能无基线：网站 JS bundle 体积、首屏 LCP、TTI 无量化阈值，重构可能悄然退化。\n2. 可访问性未审计：9 语言首页 + 文档页未跑 axe-core，键盘导航 / 屏幕阅读器 / 色彩对比度无保障。\n3. Lighthouse 未接入：Performance / A11y / Best Practices / SEO 无 CI 拦截，低于业界标准的合并可能进入 main。\n4. Go public API 文档缺失：pkg/... 是面向宿主 CLI 的稳定接口，但 go doc 注释未渲染到文档站，外部开发者只能读源码。\n\n## 决策\n\n### 1. 性能基线（perf budget）\n\n- 新增 website/scripts/perf-budget.mjs：解析 
ext build 产物的 .next/static/chunks/*.js，累加初始包 JS 体积（gzipped）\n- 阈值：初始包 ≤ 200 KB gzipped，超出 CI fail\n- 报告写到 website/.perf-budget.json，附 PR comment\n\n### 2. 可访问性（a11y）\n\n- 引入 xe-core/playwright 在 GitHub Actions 真实浏览器跑 9 语言首页 + 文档页\n- 阈值：0 严重违规（serious/critical），普通违规 ≤5 处作为 warning\n- 输出 SARIF → Code Scanning Alerts\n\n### 3. Lighthouse CI\n\n- 配置文件 .lighthouserc.cjs：仅跑 desktop preset，针对首页 /[locale]/ 4 个核心 locale（en/zh/ja/ko）\n- 4 项基线：Performance ≥90、A11y ≥95、Best Practices ≥95、SEO ≥95\n- 失败策略：低于阈值 → blocking check；分数下降 >5 → warning\n\n### 4. Go public API 文档\n\n- 新增 internal/godocgen/main.go：遍历 pkg/... 包，用 go/doc 提取 exported 符号，渲染为 Markdown\n- 输出路径：website/content/docs/api/{locale}/index.md + pkg-{name}.md\n- 9 语言 i18n 标题 + 描述字符串，仅英文版本含完整 Go API 内容（其他语言说明参见英文）\n- CI 中跑 go doc ./... 校验文档与代码同步\n\n### 5. 治理工作流整合\n\n- 新增 .github/workflows/governance.yml：单一入口跑 lighthouse + a11y + bundle + godoc\n- 与 ci.yml（Go 单元测试）、docs-site.yml（静态部署）、elease.yml（goreleaser）解耦，单独失败不阻断其它流程\n\n### 6. 维护规范\n\n- 新增 docs/standards/maintenance.md：每季度回归清单（依赖更新 / 漏洞扫描 / Lighthouse 重测 / Go API 文档同步）\n- CONSTRAINTS.md 增补四项新阈值\n\n## 后果\n\n### 正面\n\n- 重构有量化门禁，bundle 退化 / a11y 退化 / SEO 退化都能在 PR 阶段拦截\n- Go public API 进文档站，外部宿主开发者可读 go.dev 风格文档\n- 4 项工作流并行：单元测试 / 静态部署 / 发布 / 治理互不阻塞\n- 长期治理责任落到 docs/standards/maintenance.md，避免治理项被遗忘\n\n### 负面 / 权衡\n\n- CI 时间增长约 +3 min（lighthouse + axe 是重头）\n- godoc 生成依赖 go/doc，未来 Go 版本升级需关注 API 变化\n- Lighthouse CI 首次跑分可能低于阈值，需手动 --assert.assertMatrix 锁定当前分数后再逐步提升\n- axe-core 不覆盖屏幕阅读器实际行为，仍需季度人工抽样复核\n\n### 风险与缓解\n\n| 风险 | 缓解 |\n|---|---|\n| Lighthouse 分数不稳定（网络/资源） | 使用 lighthouserc.cjs 的 staticDistDir 模式跑本地构建，固定环境 |\n| axe-core 在 next-intl hydration 后报错 | 用 Playwright 等待 
etworkidle 后再断言 |\n| godoc 输出污染文档站 git 树 | website/content/docs/api/ 加入 .gitignore，CI 用 artifact 上传 |\n| goreleaser 不识别 v0.3.0 | 复用 release.yml，CHANGELOG 引用本次 ADR |\n\n## 后续\n\n- v0.3.0 发布时同步宣告本 ADR\n- 下一阶段可考虑：OpenAPI/Swagger UI（API 文档）、Playwright 真实端到端回归、性能火焰图归档\n

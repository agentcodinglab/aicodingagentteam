# ADR-0006: 治理引擎 fail-open 设计

> 状态：已接受
> 日期：2026-09-02

## 背景

治理引擎（113+ 规则）在代码写入前、CI、质量门禁时执行。需决定治理引擎故障时是阻断还是放行。

## 决策

**fail-open：治理引擎内部异常时默认返回通过，不阻断开发流程。**

关键理由：
1. **工具不应阻塞业务**：治理工具自身故障不应阻断软件开发
2. **质量门禁兜底**：治理是前置拦截，最终质量由 Quality-Gate 确定性校验把关
3. **可观测**：fail-open 时记录 WARN 日志和审计，不静默
4. **可配置**：关键路径可配置 fail-close（如 CI 模式）

淘汰方案：fail-close 会导致工具自身 bug 变成开发阻塞，用户体验差。

## 后果

- 正面：治理工具故障不影响开发，用户体验好
- 负面：故障期间不合规代码可能通过（但质量门禁会兜底）
- 后续：需在审计日志中明确标记 fail-open 事件，便于追溯
